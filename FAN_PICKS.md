# Fan picks, consensus and optional nickname leaderboard

Uses the already connected private Vercel Blob store under `canu/consensus/v1/`. No Supabase, external provider installation, or new credential is required. Only votes, rate-limit markers and optional public nickname records are added; live-history files are untouched.

Fans pick a winner on game cards, above the existing forecast and leader sections, and can also vote in the pregame centre. Consensus is share of fan choices, not a probability estimate. Counts start at zero without fabricated seed votes. An optional public nickname joins the weekly/season leaderboard (Explore → Fan Picks & Leaderboard). One correct winner earns one point, using verified final result sources already refreshed by the site's existing data workflow. Ties do not earn points. A fan can leave the leaderboard while keeping anonymous votes, or clear a pick before kickoff. No Tom/Zach selections or endorsement claims are added.

The server creates a 256-bit random, host-only Secure/HttpOnly/SameSite=Strict cookie. Its SHA-256-derived ID identifies private votes; raw cookie credentials are never stored in records, URLs or public responses. One vote per browser per game is counted; changes append immutable records and the latest valid record wins. The provider's upload timestamp must precede both the recorded and current kickoff. A request that crosses kickoff cannot create a late counted vote. Revisions avoid read-modify-write races. Server-controlled kickoff/status rejects late, final, cancelled, postponed, exhibition and unresolved matchups. Unknown kickoff times keep voting closed. Same-origin JSON requests, input validation and atomic per-IP rate slots protect writes.

Nicknames are opt-in and unverified. Browser identities are not verified humans: another browser or cleared cookies can create a new entry. This is a casual free fan competition, not authenticated cross-device accounts or a prizes system. No account recovery is promised in this version. The short leaderboard tag distinguishes identical names. Future verified login can merge browser identities with explicit user consent.

Storage caps are explicit: 10,000 records per poll scan and 500 named participants in the first-version leaderboard. A limit returns unavailable instead of silently dropping data. Polls and standings use up to 20-second warm-instance caches; client refresh is every 30 seconds, and responses with browser-specific choices are never CDN-cached. Vercel Cron deletes rate markers older than 24 hours daily using the existing CRON_SECRET. Votes remain private and are not deleted by housekeeping. Blob usage counts toward the existing plan.

Validation: `node tests/fan-consensus.cjs`, game-day and compact-pregame regressions; local UI vote/change/reload/nickname/rank checks; production persisted vote verification and cleanup of generated verification data; desktop and 320–430px mobile layouts. No live results or public fan votes are fabricated for tests.
